# Композиция и поведение главной

## Context

`Home.tsx` собирает девять блоков. Старые требования к противоречию на первом экране, пяти вкладкам, карточкам, схеме и их обязательным пометкам закреплены также в проверках статического HTML и браузера. Дельта для `web/site` заменяет эти контракты вместе с композицией. Поток работы в редакторе описан в ADR-005 и ADR-006. Демонстрации на сайте автономны, кадры хранятся локально.

## Goals / Non-Goals

Одного взгляда должно хватать, чтобы узнать сценарный редактор и найти кнопку заявки. Подробности открываются в месте, где возник вопрос. На сайте используются только демонстрационные материалы. Изменения в модель, пользовательские истории и их хранение выходят за границы дизайна.

## Decisions

1. **Сначала редактор.** За основу взять проверенный кадр `site/public/shots/suggestion-{720,1440}.webp` с реальной правкой «Он утонул. Всё.» → «Утонул. Всё.». Сохранить узнаваемое окружение, выделить читаемый фрагмент на узком экране с помощью кадрирования. Дать изображению содержательное текстовое описание. CTA ведёт к существующему `#beta`, вход доступен в шапке. Разыгрывать ситуацию из двух сцен здесь больше не требуется.
2. **Три вопроса.** Нативные раскрытия с вопросом на кнопке-заголовке и коротким готовым ответом внутри. Для деталей взять реплики Коли и Ани из сцен 5 и 6, для героя — сведения из карточки Коли, для сокращения — реальную правку про чашку в сцене 6. Материал находится в `site/src/content/demo.ts`. Показ ответа начинается сразу. Все ответы присутствуют в пререндере, пример можно прочесть без гидратации.
3. **Два входа в один разбор.** Согласованный разговор воспроизводится дословно. Сразу под репликой — нативное свёрнутое раскрытие «Откуда взялась эта подсказка?». Внутри короткие пометки связывают конкретные слова с двумя сценами, характером братьев, подтекстом и восприятием зрителя. Слова «рука высунется» в самом ответе ведут к адресуемой пометке о ключе внутри того же разбора. При активации раскрыть раздел и привести нужную пометку в поле зрения с различимой подписью, сохраняя логичный фокус. На телефоне пометка читается в том же потоке. Нативное раскрытие доступно без скриптов. Проверить переход к фрагменту из обоих состояний и повторное сворачивание. Постоянная схема со стрелками потребовала бы расшифровки ещё до чтения сцены.
4. **Редакционные основания.** Пометка о восприятии зрителя опирается на Дэвида Бордуэлла, *Narration in the Fiction Film* из `coauthor-context/Книги по сценариям/`. В разборе своими словами показать, как знакомая зрителю черта придаёт смысл жесту. Атрибуция относится к подходу, сцена с братьями принадлежит примеру для сайта. Использовать формулировку «Мы создаём ИИ…» из замысла, чтобы этот разбор читался как иллюстрация подхода команды.
5. **От примера к своему файлу.** Коротко показать открытие поддерживаемого файла и работу над драфтом в редакторе. Это иллюстрация пути автора, без загрузки рукописи на лендинг. Затем — согласованное обращение команды. Сохранить девиз Бергмана рядом с обращением, где у него есть контекст, без самостоятельного экрана. Форму `BetaForm` использовать в прежнем контейнере `#beta`, с согласованным заголовком, затем показать сокращённый FAQ. Обновить указания «ниже/выше» по фактическому расположению формы.
6. **Проверять историю на готовой странице.** Актуализировать существующие `check-build.mjs` и `check-behaviour.mjs`. Сохранить независимые проверки юридических документов, метаданных, формы, бюджета скриптов и доступности. Использовать текущий пререндеринг, стили и токены сайта. В работе с иллюстрациями учитывать потребителей ресурсов на остальных страницах.

## Risks / Trade-offs

- На телефоне полное окно редактора превращается в миниатюру → сверить кадрирование на 390 px и убедиться, что реплика и предложение читаются при обычном масштабе.
- Объяснения заглушают финал → сначала показать диалог целиком, источники оставить в раскрытии. Основная страница читается при выключенном JavaScript и в режиме уменьшенного движения.
- Сцену принимают за реальный лог диалога → подписать редакционный пример, реальные кадры беты маркировать отдельно.
- Старые ожидания в тестах могут закрепить удалённые блоки → заменить их проверками новой последовательности и обоих путей в разбор.
