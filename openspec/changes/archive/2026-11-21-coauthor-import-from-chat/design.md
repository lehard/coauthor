# Design: импорт файла из чата соавтором

## Context

Мотивация — в proposal.md. Что уже есть в коде:

- `agno/core/imports.py`: `parse_manuscript(extension, data)` разбирает Fountain, FDX, STARC, DOCX и TXT в `Doc`
  редактора; `_add_cast_and_places` добавляет недостающих персонажей и локации; `import_into` заменяет текст драфта и
  принимает только `purpose` `import` (`_manuscript`); `create_project_from_file(connection, owner, title, name,
  data)` создаёт историю из байтов и сохраняет файл с `purpose` `import`.
- `agno/core/drafts.py`: `create_draft(connection, project_id, name, base_id, user_id)` копирует документы основы и
  текст сценария без меток; основа может быть заперта (проверяется только корзина).
- `agno/core/files.py`: `ALLOWED["chat"]` шире `ALLOWED["import"]`; `file_format(name, "import", data)` отказывает
  с перечнем форматов импорта.
- `agno/core/texts.py`: `scenes(doc)` делит текст на сцены (заголовок и абзацы до следующего заголовка, группы или
  акта), `block_text` даёт текст абзаца.
- `agno/core/review.py`: проверка абзацев предложения отказывает на `\n` и `\r`.
- `agno/agents/coauthor_tools.py`: `read_chat_file` и `save_chat_file_to_notes` проверяют, что файл из этой беседы
  (`stored.session_id == run_context.session_id`); `_done(text, target_type, id, **extra)` — сделанное для чата.
- `web/src/screens/project/chat/actions.ts`: `CHANGING_TOOLS`, заголовки карточек, `targetRef` (только цели внутри
  драфта беседы) и `changedResources` (ресурсы Refine для обновления).
- Редактор хранит перенос строки внутри абзаца символом `\n` (стиль `white-space: pre-wrap`); «Принять» абзацами
  делает `schema.text(p.text)`, то есть вставляет `\n` как есть. Карточка предложения (`SuggestionViews.tsx`) выводит
  `p.text` в `<span>` без `whitespace-pre-line`.
- Предела числа драфтов истории нет (`count_drafts` используется только для запрета удалить последний).

## Goals / Non-Goals

**Goals:**
- Один разбор на все пути: кнопка, история из файла, новый драфт из чата и сцены для вставки дают одинаковые абзацы.
- Без новой схемы базы и без нового назначения файла.
- Отказы — явные, с причиной; подмены формата и частичного импорта нет.

**Non-Goals:**
- Перенос параметров сцены STARC (название, день, цвет, теги) во вставку предложением: у абзаца предложения есть
  только тип и текст. Новый драфт из STARC переносит их, как импорт кнопкой.
- Отметка импорта в журнале написанных слов: новый драфт из файла — не правка автора, как и импорт кнопкой.

## Decisions

### 1. Файл беседы разбирается на месте, без копии и нового назначения

Ядро получает файл беседы по `id`, проверяет историю и формат (`file_format(name, "import", data)`) и вызывает
`parse_manuscript`. Новая общая функция `_chat_manuscript(connection, project_id, file_id)` рядом с `_manuscript`:
требует `purpose` `chat` и историю файла. Проверку беседы (`session_id`) делает инструмент, как у
`read_chat_file`: это граница беседы, а не ядра.

Альтернатива — копия файла с `purpose` `import` перед импортом: лишняя запись и место без пользы, у нового драфта
файл импорта нигде не показывается. История из файла по-прежнему сохраняет копию с `purpose` `import`: этого
требует «Новая история из файла», а файл беседы остаётся в старой истории.

### 2. Новый драфт: копия основы, затем текст из файла в той же транзакции

`create_draft_from_chat_file(connection, project_id, base_id, file_id, name, user_id)` в `imports.py`:
1. разобрать файл (отказ — до любой записи);
2. `create_draft` от основы — драфта беседы;
3. записать `manuscript.doc` в текст сценария нового драфта через `write_text`, без снимка: прежний текст — копия
   основы, у нового драфта ещё нет своей истории;
4. `_add_cast_and_places` для нового драфта.

Всё в одной транзакции `get_engine().begin()` инструмента. Возвращает драфт и `skipped`. Запертая основа не мешает:
`create_draft` проверяет только корзину, новый драфт не заперт.

Альтернатива — `import_into` в новый драфт: он требует `purpose` `import`, ревизию и делает снимок `import` с
копией основы, что сбивает автора в «Сохранениях» нового драфта.

### 3. Новая история: существующий `create_project_from_file` с байтами файла беседы

Инструмент читает имя и байты файла беседы и вызывает `create_project_from_file(connection, user, title, name,
data)`. Внутри уже есть `check_upload` (размер, тип для `import`, ClamAV) и сохранение копии `import`. Повторная
проверка антивирусом — та же, что при загрузке из меню; отдельного пути без неё не делаем. Сбой ClamAV — отказ,
как у загрузки.

### 4. Сцены файла: список и одна сцена за вызов

`chat_file_scenes(connection, project_id, file_id)` в `imports.py` разбирает файл и отдаёт `texts.scenes(doc)`;
каждый абзац — `{type: block["type"], text: block_text(block)}`, заголовок сцены — первый абзац. Инструмент
`read_chat_file_scenes(file_id, scene=0)`: `0` — список сцен (номер, заголовок, число абзацев), `N` — абзацы сцены
`N`. Абзацы вне сцен (до первого заголовка, акты и группы) этим инструментом не читаются; для них есть
`read_chat_file`. Это ограничение называет описание инструмента.

Альтернатива — режим в `read_chat_file`: смешивает плоский текст всех форматов и типы форматов импорта в одном
контракте, а PDF и MD в нём остаются текстом. Отдельный инструмент проще описать модели и проверить.

Одна сцена за вызов ограничивает размер ответа. Длинный файл не попадает в контекст целиком.

### 5. Перенос строки в абзаце предложения

В `review.py` проверка абзаца отказывает только на `\r`; `\n` остаётся в тексте. Сообщение отказа и описание
`suggest_edit` говорят: перенос строки внутри абзаца — `\n`, как в файле; новая строка другого типа — отдельный
абзац. На фронтенде:
- блок предложения в тексте рисуется элементами редактора, у которых уже `pre-wrap`; это проверяется сценарием,
  код меняется, только если проверка покажет склейку;
- карточка: `whitespace-pre-line` у текста абзаца в `SuggestedText`.

Предложение строкой (`replace` с `text`) не меняется: строка заменяет цитату внутри одного абзаца.

### 6. Инструменты соавтора и права

| Инструмент | Список | Право (`members.Need`) |
| --- | --- | --- |
| `read_chat_file_scenes(file_id, scene=0)` | `READING_TOOLS` | `read` |
| `import_chat_file_as_draft(file_id, name)` | `CHANGING_TOOLS` | `edit` |
| `create_story_from_chat_file(file_id, title)` | `CHANGING_TOOLS` | `edit` в истории беседы |

`name` и `title` обязательны, без значений по умолчанию: промпт велит передавать имя файла без расширения, если
автор не назвал другое. Файл не из этой беседы — отказ «файл не найден в этой беседе», как у `read_chat_file`.

Сделанное:
- новый драфт — `_done("Создан драфт «…» из файла «…»", "draft", draft.id, project=str(project_id))`;
- история — `_done("Создана история «…» из файла «…»", "project", project.id, draft=str(draft_id))`.

Пропущенные записи STARC добавляются в текст `done` («не перенесены: сценарий «Выбор 2», локация «Колиба»»).

### 7. Чат

`actions.ts`:
- оба имени в `CHANGING_TOOLS`;
- карточки «Импортировать файл в новый драфт «<name>»» и «Создать историю «<title>» из файла»;
- `Target` получает необязательные `project` и `draft`;
- новая `targetPath(current, target)` вместо пары `docPath(data.draft, targetRef(...))` в `ActionLines.tsx`:
  - `draft` → `/p/<project>/d/<id>/text`;
  - `project` → `/p/<id>/d/<draft>/text`;
  - остальные цели — как сейчас;
- `changedResources`: `draft` → `drafts`, `project` → `projects`.

Цель без нужного поля (`draft` без `project`) — нечитаемый результат: строка «Не удалось прочитать результат
действия», без подстановки текущего драфта. Беседа остаётся в своём драфте.

### 8. Промпт и справка

`agno/skills/coauthor/SKILL.md`:
- «импортируй / загрузи как сценарий» — `import_chat_file_as_draft`;
- «сделай новую историю из файла» — `create_story_from_chat_file`;
- «вставь сцену / кусок из файла» — `read_chat_file_scenes` и `suggest_edit` с абзацами как есть;
- PDF и MD — `read_chat_file` и своя разметка; на просьбу импортировать их — сказать, что импорт их не разбирает,
  и предложить заметку или вставку предложением.

Справка «О сервисе «Соавтор»» получает строку об импорте из чата. Замена текста текущего драфта — только кнопкой.

### 9. Замер действий

- `actions.toml`: поля `file` (имя файла в `agno/evals/coauthor/files/`) и `file_scene` (номер сцены для
  `suggest_edit`). `NEEDS_FILE` сужается до `save_chat_file_to_notes` и `create_story_from_chat_file`.
- Перед запуском просьбы `actions_run.py` загружает файл в историю просьбы с `purpose` `chat` и `session_id`
  беседы (`core.files.upload_file`) и добавляет в зависимости запуска ту же запись «Файлы этого сообщения (id и
  имя)», что чат, а текст сообщения — «Файлы: <имя>».
- Проверка:
  - для `import_chat_file_as_draft` — новый драфт ищется по разнице списка драфтов истории до и после, текст
    сравнивается с `parse_manuscript` по типам и текстам абзацев;
  - для `file_scene` — абзацы предложения сравниваются с абзацами сцены.
- Файлы набора: один Fountain с несколькими сценами, в одной из них реплика с переносом строки. Пишется вручную по
  демо-миру.

## Risks / Trade-offs

- [Беседа остаётся в старом драфте, автор может ждать перехода] → Строка о сделанном ведёт в новый драфт, справка
  говорит, что беседы драфта остаются в нём.
- [Сцена файла больше 300 абзацев не уходит одним предложением] → Отказ ядра с пределом. Соавтор делит вставку
  или советует импорт в новый драфт. Подмены нет.
- [Параметры сцены STARC теряются во вставке предложением] → Записано в Non-Goals. Для полного переноса — новый
  драфт из файла.
- [Повторный ClamAV при новой истории добавляет задержку] → Тот же путь, что у истории из файла в меню. Файл до
  20 МБ.
- [Модель путает «импортируй» и «вставь»] → Промпт с примерами и просьбы замера на оба пути. В обоих случаях текст
  текущего драфта не меняется без автора.

## Migration Plan

Миграций нет. Изменение выходит одним релизом: бэкенд (инструменты, проверка абзацев) и фронтенд (цели, карточки,
перенос строки). Откат — релиз предыдущей версии. Предложения с `\n`, созданные до отката, остаются в базе;
старый фронтенд покажет их без переноса на карточке и примет как есть.
