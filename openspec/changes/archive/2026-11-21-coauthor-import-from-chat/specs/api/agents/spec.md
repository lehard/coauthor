## MODIFIED Requirements

### Requirement: Инструменты соавтора
Соавтор MUST иметь инструменты ядра. Читающие: список документов драфта, чтение документа, чтение текста сценария целиком или сцены по `uid`, чтение текста файла беседы, сцены файла беседы с типами абзацев (требование «Сцены файла беседы»), список и чтение заметок истории, поиск по драфту и истории беседы (тот же поиск ядра, что у маршрута «Поиск по драфту истории» `api/stories`: сцены с `uid`, документы и заметки с `id` и кусочком текста вокруг совпадения; короткий запрос — отказ с причиной), список каркасов историй с актами и точками, поиск по библиотеке первоисточников и оформление цитаты из неё (`sources/library`: «Поиск по библиотеке», «Проверка цитаты»). Кроме инструментов ядра — читающий поиск в интернете через Yandex Search API (`integrations`: «Yandex Search API»): до 5 результатов с заголовком, адресом и отрывками; в одном запуске MUST уходить не больше 2 запросов к поиску, следующий вызов MUST возвращать отказ без запроса; сбой поиска MUST давать отказ с причиной, без запасного поисковика; в лог MUST NOT попадать текст запроса. Предлагающие: создание предложения правки. Меняющие (требование «Действия соавтора»): создание и изменение заметки, сохранение файла беседы в заметку, новый драфт из файла беседы и новая история из файла беседы (требования «Новый драфт из файла беседы», «Новая история из файла беседы»), создание персонажа, локации или мира, изменение документа драфта, комментарий к цитате сцены. Поиск в интернете, как и инструменты ядра, MUST работать только в беседе драфта, который спрашивающий может читать. Драфт определяется только беседой (`session_id` вида `<projectId>:<draftId>:<uuid>`), пользователь — только запуском; доступ — только у владельца истории. Других изменений инструментами MUST NOT быть: удаления, корзины и восстановления, принятия и отклонения предложений, решения веток и правки сообщений, изменения текста сценария, изменения и удаления драфтов и историй, версий, оригиналов заметок и импорта в существующий драфт.

#### Scenario: Чтение персонажа
- GIVEN в драфте беседы есть персонаж «Вера» с полем «Главный страх»
- WHEN автор спрашивает в чате без открытого документа «Чего боится Вера?»
- THEN соавтор MUST прочитать профиль инструментом и опираться на этот страх

#### Scenario: Чужая история
- GIVEN беседа с `session_id` вида `<projectId>:<draftId>:<uuid>` истории другого пользователя
- WHEN инструмент вызывается в запуске этого пользователя
- THEN инструмент MUST вернуть отказ «история не найдена» без данных истории

#### Scenario: Беседа без истории
- GIVEN `session_id` беседы не содержит id истории и драфта
- WHEN соавтор вызывает любой инструмент ядра
- THEN инструмент MUST вернуть отказ с причиной, а не данные другой истории

#### Scenario: Документ другого драфта
- GIVEN беседа драфта 2
- WHEN соавтор читает документ драфта 1 по его `id`
- THEN инструмент MUST вернуть отказ «документ не найден»

#### Scenario: Драфт в корзине
- GIVEN драфт беседы лежит в корзине
- WHEN соавтор вызывает инструмент
- THEN инструмент MUST вернуть отказ с причиной

#### Scenario: Заметка в чате
- GIVEN в истории беседы есть заметка «Финал», и она не открыта на экране
- WHEN автор спрашивает «Что у меня в заметке про финал?»
- THEN соавтор MUST прочитать заметку инструментом и опираться на её текст

#### Scenario: Удалить нельзя
- GIVEN автор просит «удали персонажа Пётр»
- WHEN соавтор отвечает
- THEN персонаж MUST остаться вне корзины, а соавтор MUST сказать, что удаляет только автор

#### Scenario: Каркасы из ядра
- WHEN соавтор вызывает инструмент списка каркасов
- THEN ответ MUST содержать те же каркасы, акты, точки и подсказки, что `GET /api/v1/story-templates`

#### Scenario: Поиск по истории
- GIVEN в драфте беседы лодка упоминается в двух сценах и в профиле Коли
- WHEN автор спрашивает «В каких сценах есть лодка?»
- THEN соавтор MUST найти их инструментом поиска без подтверждения автора и назвать эти сцены по номерам, а не читать для этого весь текст сценария

#### Scenario: Задание среди меняющих
- GIVEN режим соавтора — `ask`
- WHEN соавтор пишет задание на исследование
- THEN запуск MUST NOT вставать на паузу: задание — текст ответа, а не действие

#### Scenario: Поиск по библиотеке без подтверждения
- GIVEN режим соавтора — `ask`
- WHEN соавтор ищет в библиотеке первоисточников или оформляет цитату
- THEN запуск MUST NOT вставать на паузу

#### Scenario: Сбой поиска по библиотеке
- GIVEN модель эмбеддингов недоступна
- WHEN соавтор ищет в библиотеке
- THEN инструмент MUST вернуть отказ о сбое поиска, а не «ничего не нашлось»

#### Scenario: Поиск в интернете без подтверждения
- GIVEN режим соавтора — `ask`
- WHEN соавтор ищет в интернете
- THEN запуск MUST NOT вставать на паузу

#### Scenario: Третий поиск в запуске
- GIVEN в этом запуске соавтор уже дважды искал в интернете
- WHEN он вызывает поиск в третий раз
- THEN инструмент MUST вернуть отказ о пределе поисков, а запроса к Yandex Search API MUST NOT быть

#### Scenario: Сбой поиска в интернете
- GIVEN Yandex Search API отвечает ошибкой (например, неверный ключ или исчерпанная квота)
- WHEN соавтор ищет в интернете
- THEN инструмент MUST вернуть отказ о сбое поиска, а не «ничего не нашлось»
- AND в логе API MUST быть ошибка с кодом ответа и MUST NOT быть текста запроса

#### Scenario: Ничего не нашлось в интернете
- GIVEN Yandex Search API вернул выдачу без результатов
- WHEN соавтор ищет в интернете
- THEN инструмент MUST сказать, что ничего не нашлось, и не выдумывать результатов

#### Scenario: Сцены файла без подтверждения
- GIVEN режим соавтора — `ask`, к сообщению приложен Fountain-файл
- WHEN соавтор читает сцены этого файла
- THEN запуск MUST NOT вставать на паузу

## ADDED Requirements

### Requirement: Сцены файла беседы
Читающий инструмент MUST принимать `id` файла этой беседы и номер сцены. Без номера он MUST возвращать имя файла и список сцен, с номером — абзацы сцены `{type, text}` («Сцены файла беседы в ядре», `api/story-import`). Файл другой беседы и отказ разбора MUST давать отказ с причиной; для PDF и MD отказ MUST говорить, что такой файл читается только текстом. Инструмент MUST быть доступен всем, кто читает драфт беседы.

#### Scenario: Список сцен
- GIVEN к сообщению приложен `Паром.fountain` с тремя сценами
- WHEN соавтор читает сцены файла без номера
- THEN ответ MUST содержать три сцены с номерами 1–3 и их заголовками

#### Scenario: PDF сценами
- GIVEN к сообщению приложен `Эпоха.pdf`
- WHEN соавтор читает его сцены
- THEN инструмент MUST вернуть отказ, что PDF читается только текстом, без попытки разбора

#### Scenario: Файл другой беседы
- GIVEN файл приложен к другой беседе этой истории
- WHEN соавтор читает его сцены
- THEN инструмент MUST вернуть отказ «файл не найден в этой беседе»

### Requirement: Новый драфт из файла беседы
Меняющий инструмент MUST принимать `id` файла этой беседы и имя драфта и создавать новый драфт на основе драфта беседы («Новый драфт из файла беседы в ядре», `api/story-import`). Роль спрашивающего MUST позволять менять историю. Сделанное MUST называть новый драфт и вести в его текст сценария, а пропущенные импортом STARC записи MUST перечисляться в ответе. Отказ MUST возвращаться текстом с причиной без изменений.

#### Scenario: Импортируй
- GIVEN режим соавтора — `auto`, автор приложил `Паром.fountain` и пишет «импортируй его»
- WHEN соавтор отвечает
- THEN в истории MUST появиться драфт «Паром» с текстом сценария из файла, текст драфта беседы MUST остаться прежним
- AND в чате MUST быть строка о сделанном со ссылкой на новый драфт

#### Scenario: Пауза перед импортом
- GIVEN режим соавтора — `ask`
- WHEN соавтор вызывает импорт файла в новый драфт
- THEN запуск MUST встать на паузу, и драфта MUST NOT быть до ответа `{"accepted": true}`

#### Scenario: Импорт PDF
- GIVEN автор приложил `Эпоха.pdf` и пишет «импортируй это»
- WHEN соавтор вызывает импорт
- THEN инструмент MUST вернуть отказ с перечнем форматов импорта, драфта MUST NOT появиться, а соавтор MUST сказать автору, что PDF можно сохранить в заметки или вставить кусок предложением

#### Scenario: Рецензент просит импорт
- GIVEN спрашивающий — рецензент истории
- WHEN соавтор вызывает импорт файла в новый драфт
- THEN инструмент MUST вернуть отказ по роли, драфта MUST NOT появиться

### Requirement: Новая история из файла беседы
Меняющий инструмент MUST принимать `id` файла этой беседы и название и создавать историю пользователя запуска («Новая история из файла беседы в ядре», `api/story-import`). Соавтор MUST вызывать его только по прямой просьбе сделать из файла новую историю; на «импортируй это» MUST создаваться новый драфт. Роль спрашивающего MUST позволять менять историю беседы. Сделанное MUST вести в текст сценария первого драфта новой истории.

#### Scenario: Сделай новую историю
- GIVEN режим соавтора — `auto`, автор приложил `Паром.fdx` и пишет «сделай из этого новую историю»
- WHEN соавтор отвечает
- THEN у автора MUST появиться история «Паром» с текстом из файла, а в истории беседы MUST NOT появиться новых драфтов

#### Scenario: Импортируй без истории
- GIVEN автор приложил `Паром.fountain` и пишет «импортируй»
- WHEN соавтор отвечает
- THEN новой истории MUST NOT появиться, а в истории беседы MUST появиться новый драфт

### Requirement: Вставка из файла беседы
На просьбу вставить часть файла беседы в текст сценария («вставь вторую сцену из файла после сцены в баре») соавтор MUST для файла формата импорта взять абзацы инструментом «Сцены файла беседы» и предложить их `suggest_edit` с подходящим местом, с теми же типами, текстом и переносами строк, без переразметки и пересказа. Для PDF и MD соавтор MUST читать файл текстом и размечать абзацы сам. Текст сценария MUST NOT меняться без предложения.

#### Scenario: Сцена из файла после сцены
- GIVEN автор приложил `Паром.fountain`, где вторая сцена — заголовок, описание действия, «ДАРЬЯН» и реплика «Фыва\nывафы», и в драфте есть сцена в баре
- WHEN автор пишет «вставь вторую сцену из файла после сцены в баре»
- THEN `GET …/suggestions?status=open` MUST вернуть одно предложение с местом `scene_end` у сцены в баре или `after` у её последнего абзаца и абзацами второй сцены файла с их типами и текстом «Фыва\nывафы»
- AND текст сценария MUST NOT измениться
