## MODIFIED Requirements

### Requirement: Проверка абзацев предложения
Абзацы предложения MUST быть непустым списком из не более 300 элементов `{type, text}`: `type` — один из 14 типов абзацев редактора, `text` — непустая строка; перенос строки `\n` внутри абзаца MUST сохраняться как часть его текста, так же как его хранит текст сценария после импорта (`api/story-import`, «Абзацы сценария из файла»), а возврат каретки `\r` MUST давать отказ; ремарка — без обрамляющих скобок, их добавляет оформление. Иначе MUST быть отказ с причиной, предложение MUST NOT создаваться, тип MUST NOT подменяться.

#### Scenario: Неизвестный тип
- WHEN соавтор предлагает абзац с типом `speech`
- THEN ядро MUST отказать с причиной, называющей тип, и предложение MUST NOT появиться

#### Scenario: Ремарка в скобках
- WHEN соавтор предлагает абзац `parenthetical` «(тихо)»
- THEN ядро MUST отказать с причиной «ремарку пиши без скобок», и предложение MUST NOT появиться

#### Scenario: Пустой список
- WHEN соавтор предлагает место `scene_end` без абзацев
- THEN ядро MUST отказать с причиной, и предложение MUST NOT появиться

#### Scenario: Реплика в две строки
- WHEN соавтор предлагает абзац `dialogue` с текстом «Фыва\nывафы»
- THEN предложение MUST появиться, и `GET …/suggestions?status=open` MUST вернуть этот абзац с текстом «Фыва\nывафы», без замены переноса пробелом и без деления на два абзаца

#### Scenario: Возврат каретки
- WHEN соавтор предлагает абзац с текстом «Фыва\r\nывафы»
- THEN ядро MUST отказать с причиной, и предложение MUST NOT появиться
