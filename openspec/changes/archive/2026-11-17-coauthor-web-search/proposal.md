# Proposal: соавтор ищет факты в интернете через Yandex Search API

Источник: `business-intents/coauthor-web-search.md` (решения владельца 2026-11-16 и 2026-11-17).

## Why

Соавтор работает на DeepSeek через API, а у API своего поиска нет. О внешнем мире (быт эпохи, профессия, место, дата) он отвечает по памяти модели с оговоркой «стоит проверить» и может выдумать. Владелец выбрал обычный синхронный поиск Yandex Search API: у Яндекса лучший индекс рунета, расчёты в рублях, сервис российский, и это 0,488 ₽ за запрос против 1,5 ₽ у смарт-сниппетов и 5 ₽ у генеративного ответа.

## What Changes

- У соавтора появляется читающий инструмент `web_search(query)`, без подтверждения автора. Он делает синхронный запрос к Yandex Search API v2 (`SEARCH_TYPE_RU`, регион Россия `225`, XML) и возвращает модели до 5 результатов: номер, заголовок, адрес и до 5 отрывков у каждого.
- За один запуск соавтора уходит не больше 2 запросов к Яндексу. Третий вызов возвращает отказ, к Яндексу не обращаясь.
- Сбой Яндекса (ошибка HTTP, квота, неверный ключ, нераспознанный ответ) даёт отказ инструмента с причиной и ошибку в логе API, без текста запроса. Повтора и запасного поисковика нет.
- Без `YANDEX_SEARCH_API_KEY` и `YANDEX_CLOUD_FOLDER_ID` API не стартует.
- Поиск оплачивается из лимита автора. В файле цен биллинга появляется цена инструмента: `web_search` 0,488 ₽ за вызов в любое время суток. Биллинг ведёт отдельный журнал вызовов платных инструментов по запуску, расход периода и отчёт `report` его учитывают. Без цены `web_search` API не стартует. Оплачивается только поиск, который вернул выдачу, в том числе пустую.
- Промпт соавтора. Искать в интернете он должен только факты внешнего мира. О самой истории он ищет `search_story`, о ремесле `search_sources`. В запрос не попадает текст сценария и личные данные. Найденное он подаёт со ссылками, а если не нашёл или поиск отказал, говорит об этом. Справка о сервисе дополняется поиском.
- «Факты реального мира в ответе соавтора» меняются. Факт по найденному подаётся со ссылками на источник. Оговорка «стоит проверить» остаётся для сведений без источника.
- Просьба «изучить тему» по-прежнему ведёт к заданию на исследование. Соавтор не подменяет его своими поисками и не утверждает, что исследовал тему.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `api/agents`:
  - «Инструменты соавтора» — новый читающий инструмент поиска в интернете, предел 2 поиска на запуск, отказ при сбое.
  - «Факты реального мира в ответе соавтора» — сведения по найденному даются со ссылками, оговорка остаётся для сведений без источника.
  - «Задание на исследование у соавтора» — просьба изучить тему не подменяется поиском.
  - «Справка о сервисе у соавтора» — справка упоминает поиск в интернете.
- `integrations`: новое требование «Yandex Search API» (ключ, каталог, регион, формат, старт без настроек).
- `billing/subscriptions`:
  - «Цены моделей как данные» — в файле цен появляются цены платных инструментов.
  - «Журнал расхода соавтора» — журнал записывает и платные вызовы инструментов.
  - «Команды администратора» — `report` показывает число платных поисков.
- `billing/module`:
  - «Интерфейс биллинга» — запись расхода принимает и платные вызовы инструментов.
  - Новое требование «Таблица журнала вызовов инструментов биллинга».

## Scope

- `agno/agents/`: клиент Yandex Search API и инструмент `web_search`, его место в `READING_TOOLS`, подсчёт поисков запуска в `coauthor_usage.py`, проверка настроек и цены при старте.
- `agno/billing/`: цены инструментов в `model_prices.toml` и `plans.py`, `RunUsage` с вызовами инструментов, новая таблица и миграция `b0002_*`, расход периода и отчёт.
- `agno/admin/` (столбец поисков в `report`), `agno/skills/coauthor/SKILL.md`, `example.env`, README (настройки).
- Тесты pytest на реальном PostgreSQL: разбор XML на сохранённом образце, предел поисков, цена и журнал вызовов, расход периода.
- Ручная проверка на стенде с настоящим ключом, результат в `tmp/VERIFY.md`.

## Non-goals

- Чтение страницы целиком по ссылке, генеративный ответ, смарт-сниппеты, поиск картинок.
- Кэш одинаковых запросов, ночная цена.
- Запасной поисковик и повтор при сбое Яндекса.
- Поиск у других агентов. Parallel в реестре Studio и его спека не меняются.
- Отдельный блок ссылок в интерфейсе чата.
- Прогоны evals и судьи (ответ соавтора проверяется глазами на стенде).

## Impact

- Новая внешняя зависимость: Yandex Search API (`searchapi.api.cloud.yandex.net`), сервисный аккаунт с ролью `search-api.webSearch.user`. Ключ на сервере кладётся в `/etc/authorled/authorled.env`.
- Новые обязательные переменные окружения: без них не стартует ни API, ни импорт приложения в evals.
- Схема `billing`: новая таблица, миграция только вперёд.
- Запросы соавтора к поиску уходят в Яндекс. Сюжет туда не должен попадать, и держится это на правиле в промпте.
