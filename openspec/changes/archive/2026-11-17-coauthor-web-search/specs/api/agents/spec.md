## MODIFIED Requirements

### Requirement: Соавтор
Агент `coauthor` MUST отвечать по-русски, опираясь на контекст, присланный фронтендом (история, открытый документ, выделенный фрагмент), на историю беседы и на данные истории, прочитанные инструментами ядра. Его инструменты MUST быть только инструментами из требования «Инструменты соавтора»: инструментами ядра и поиском в интернете. Он MUST NOT утверждать, что изменил текст сценария, и MUST NOT сохранять память о пользователе или содержание произведения вне сессии беседы и ядра. Модель — `default_model()` через LiteLLM. Заметки, документы драфта и комментарии он MUST менять только по прямой просьбе автора и только после подтверждения вызова (требования «Подтверждение действия» и «Режим соавтора»); после изменения он MUST коротко сказать автору, что сделано.

До вызова модели соавтор MUST проверять лимит подписки пользователя, а после ответа MUST записывать расход запуска, в том числе его платные поиски в интернете, в журнал биллинга (`billing/subscriptions`: «Проверка лимита до запуска», «Журнал расхода соавтора»); лимит и журнал хук берёт только через интерфейс биллинга (`billing/module`). Отказ проверки MUST завершать запуск событием ошибки (`RUN_ERROR` в AG-UI) без вызова модели; ошибка записи расхода MUST завершать запуск событием ошибки, а не только строкой в логе. Цена модели соавтора MUST быть в файле цен, иначе API MUST NOT стартовать. Запуск, продолженный после паузы подтверждения, MUST записываться в журнал одной строкой со всеми токенами до и после паузы.

Промпт соавтора MUST браться из навыка `agno/skills/coauthor/SKILL.md` в формате Anthropic Agent Skills: заголовок с `name: coauthor` и непустым `description`, тело — промпт. Тело MUST целиком входить в системное сообщение на каждом ходу. Промпта соавтора в коде MUST NOT быть. Инструментов навыков (загрузка инструкций, справочных материалов и скриптов навыков) у соавтора MUST NOT быть.

#### Scenario: Ответ по контексту
- GIVEN контекст AG-UI содержит открытый документ «Вера» с полем «Главный страх: Что Аня узнает правду и уйдёт»
- WHEN автор спрашивает «Чего боится героиня?»
- THEN ответ MUST опираться на этот страх

#### Scenario: Промпт из навыка
- GIVEN `agno/skills/coauthor/SKILL.md` с `name: coauthor` и телом промпта
- WHEN API стартует и автор отправляет сообщение соавтору
- THEN системное сообщение хода MUST содержать тело `SKILL.md` целиком
- AND у соавтора MUST быть только инструменты из требования «Инструменты соавтора»

#### Scenario: Нет навыка
- GIVEN файла `agno/skills/coauthor/SKILL.md` нет
- WHEN запускается API
- THEN старт MUST завершиться ошибкой, называющей отсутствующий путь
- AND соавтор MUST NOT работать с запасным промптом

#### Scenario: Неверный заголовок навыка
- GIVEN в `agno/skills/coauthor/SKILL.md` нет `description` или `name` отличается от `coauthor`
- WHEN запускается API
- THEN старт MUST завершиться ошибкой, называющей файл и причину

#### Scenario: Расход записан
- GIVEN у автора есть действующая подписка с остатком лимита
- WHEN он отправляет сообщение соавтору и получает ответ
- THEN в журнале расхода MUST появиться строка этого запуска, и токены MUST совпадать с метриками запуска Agno

#### Scenario: Лимит исчерпан
- GIVEN расход автора за текущий период не меньше лимита тарифа
- WHEN он отправляет сообщение соавтору
- THEN поток AG-UI MUST завершиться `RUN_ERROR` с сообщением об исчерпанном лимите и датой обновления, модель MUST NOT вызываться

#### Scenario: Совет без просьбы действовать
- GIVEN режим соавтора автора — `auto`
- WHEN автор спрашивает «Каким мог бы быть брат Веры?»
- THEN соавтор MUST ответить вариантами в чате и MUST NOT создавать документ

#### Scenario: Расход запуска с паузой
- GIVEN режим соавтора автора — `ask`, и запуск встал на паузу перед созданием заметки
- WHEN автор нажимает «Разрешить», и запуск завершается ответом
- THEN в журнале расхода MUST быть ровно одна строка этого запуска с токенами до и после паузы

### Requirement: Инструменты соавтора
Соавтор MUST иметь инструменты ядра. Читающие: список документов драфта, чтение документа, чтение текста сценария целиком или сцены по `uid`, чтение текста файла беседы, список и чтение заметок истории, поиск по драфту и истории беседы (тот же поиск ядра, что у маршрута «Поиск по драфту истории» `api/stories`: сцены с `uid`, документы и заметки с `id` и кусочком текста вокруг совпадения; короткий запрос — отказ с причиной), список каркасов историй с актами и точками, поиск по библиотеке первоисточников и оформление цитаты из неё (`sources/library`: «Поиск по библиотеке», «Проверка цитаты»). Кроме инструментов ядра — читающий поиск в интернете через Yandex Search API (`integrations`: «Yandex Search API»): до 5 результатов с заголовком, адресом и отрывками; в одном запуске MUST уходить не больше 2 запросов к поиску, следующий вызов MUST возвращать отказ без запроса; сбой поиска MUST давать отказ с причиной, без запасного поисковика; в лог MUST NOT попадать текст запроса. Предлагающие: создание предложения правки. Меняющие (требование «Действия соавтора»): создание и изменение заметки, сохранение файла беседы в заметку, создание персонажа, локации или мира, изменение документа драфта, комментарий к цитате сцены. Поиск в интернете, как и инструменты ядра, MUST работать только в беседе драфта, который спрашивающий может читать. Драфт определяется только беседой (`session_id` вида `<projectId>:<draftId>:<uuid>`), пользователь — только запуском; доступ — только у владельца истории. Других изменений инструментами MUST NOT быть: удаления, корзины и восстановления, принятия и отклонения предложений, решения веток и правки сообщений, изменения текста сценария, драфтов, историй, версий, оригиналов заметок и импорта.

#### Scenario: Чтение персонажа
- GIVEN в драфте беседы есть персонаж «Вера» с полем «Главный страх»
- WHEN автор спрашивает в чате без открытого документа «Чего боится Вера?»
- THEN соавтор MUST прочитать профиль инструментом и опираться на этот страх

#### Scenario: Чужая история
- GIVEN беседа с `session_id` вида `<projectId>:<draftId>:<uuid>` истории другого пользователя
- WHEN инструмент вызывается в запуске этого пользователя
- THEN инструмент MUST вернуть отказ «история не найдена» без данных истории

#### Scenario: Беседа без истории
- GIVEN `session_id` беседы не содержит id истории и драфта
- WHEN соавтор вызывает любой инструмент ядра
- THEN инструмент MUST вернуть отказ с причиной, а не данные другой истории

#### Scenario: Документ другого драфта
- GIVEN беседа драфта 2
- WHEN соавтор читает документ драфта 1 по его `id`
- THEN инструмент MUST вернуть отказ «документ не найден»

#### Scenario: Драфт в корзине
- GIVEN драфт беседы лежит в корзине
- WHEN соавтор вызывает инструмент
- THEN инструмент MUST вернуть отказ с причиной

#### Scenario: Заметка в чате
- GIVEN в истории беседы есть заметка «Финал», и она не открыта на экране
- WHEN автор спрашивает «Что у меня в заметке про финал?»
- THEN соавтор MUST прочитать заметку инструментом и опираться на её текст

#### Scenario: Удалить нельзя
- GIVEN автор просит «удали персонажа Пётр»
- WHEN соавтор отвечает
- THEN персонаж MUST остаться вне корзины, а соавтор MUST сказать, что удаляет только автор

#### Scenario: Каркасы из ядра
- WHEN соавтор вызывает инструмент списка каркасов
- THEN ответ MUST содержать те же каркасы, акты, точки и подсказки, что `GET /api/v1/story-templates`

#### Scenario: Поиск по истории
- GIVEN в драфте беседы лодка упоминается в двух сценах и в профиле Коли
- WHEN автор спрашивает «В каких сценах есть лодка?»
- THEN соавтор MUST найти их инструментом поиска без подтверждения автора и назвать эти сцены по номерам, а не читать для этого весь текст сценария

#### Scenario: Задание среди меняющих
- GIVEN режим соавтора — `ask`
- WHEN соавтор пишет задание на исследование
- THEN запуск MUST NOT вставать на паузу: задание — текст ответа, а не действие

#### Scenario: Поиск по библиотеке без подтверждения
- GIVEN режим соавтора — `ask`
- WHEN соавтор ищет в библиотеке первоисточников или оформляет цитату
- THEN запуск MUST NOT вставать на паузу

#### Scenario: Сбой поиска по библиотеке
- GIVEN модель эмбеддингов недоступна
- WHEN соавтор ищет в библиотеке
- THEN инструмент MUST вернуть отказ о сбое поиска, а не «ничего не нашлось»

#### Scenario: Поиск в интернете без подтверждения
- GIVEN режим соавтора — `ask`
- WHEN соавтор ищет в интернете
- THEN запуск MUST NOT вставать на паузу

#### Scenario: Третий поиск в запуске
- GIVEN в этом запуске соавтор уже дважды искал в интернете
- WHEN он вызывает поиск в третий раз
- THEN инструмент MUST вернуть отказ о пределе поисков, а запроса к Yandex Search API MUST NOT быть

#### Scenario: Сбой поиска в интернете
- GIVEN Yandex Search API отвечает ошибкой (например, неверный ключ или исчерпанная квота)
- WHEN соавтор ищет в интернете
- THEN инструмент MUST вернуть отказ о сбое поиска, а не «ничего не нашлось»
- AND в логе API MUST быть ошибка с кодом ответа и MUST NOT быть текста запроса

#### Scenario: Ничего не нашлось в интернете
- GIVEN Yandex Search API вернул выдачу без результатов
- WHEN соавтор ищет в интернете
- THEN инструмент MUST сказать, что ничего не нашлось, и не выдумывать результатов

### Requirement: Факты реального мира в ответе соавтора
Когда для ответа нужен факт о реальном мире (история, профессии, места, техника, цены, фильмы и книги), соавтор MUST искать его в интернете и MUST подавать найденное со ссылками на страницы, по которым сделан вывод. Сведения без найденного источника (поиск ничего не дал, отказал или предел поисков исчерпан) он MUST подавать как справку с оговоркой, что их стоит проверить, и MUST NOT выдавать за найденные. О самой истории и о ремесле он MUST NOT искать в интернете: для них есть поиск по истории и библиотека первоисточников. В запрос к поиску MUST NOT попадать текст сценария, заметок и персональные данные: только короткий запрос своими словами. Точных имён, годов, цифр и названий, в которых он не уверен, соавтор MUST NOT приводить как факт; вместо них он MUST сказать, что не уверен.

#### Scenario: Деталь эпохи
- GIVEN автор пишет сцену в 1998 году
- WHEN он спрашивает «Какие удочки были у подростков в 98-м?»
- THEN соавтор MUST искать в интернете, а ответ MUST содержать ссылки на найденные страницы

#### Scenario: Поиск не помог
- GIVEN поиск в интернете отказал или ничего не нашёл
- WHEN соавтор отвечает на вопрос о факте
- THEN ответ MUST сказать, что источник не найден, и сведения по памяти MUST идти с оговоркой, что их стоит проверить

#### Scenario: Вопрос об истории без интернета
- GIVEN в драфте беседы лодка упоминается в двух сценах
- WHEN автор спрашивает «В каких сценах есть лодка?»
- THEN соавтор MUST NOT искать в интернете

#### Scenario: Запрос без текста истории
- GIVEN автор спрашивает, как в 1972 году в Москве выглядел табачный киоск, для сцены у киоска
- WHEN соавтор ищет в интернете
- THEN запрос MUST быть коротким и своими словами и MUST NOT содержать текста сцены и имён героев

#### Scenario: Список фильмов
- GIVEN автор просит посоветовать фильмы о семейных тайнах
- WHEN соавтор не уверен в годе или режиссёре фильма
- THEN он MUST NOT называть их как точный факт

### Requirement: Задание на исследование у соавтора
Просьба автора изучить тему вне истории (быт, профессия, эпоха, место, обычаи) MUST быть для соавтора просьбой написать задание на исследование: блок кода Markdown с меткой `research-brief` в ответе, без инструментов и без изменений истории. До задания соавтор MUST прочитать то, что в истории касается темы, и MUST задать одним сообщением одно-два уточнения: для чего материал (конкретные сцены или мир всей книги), место и время, что важнее. Без уточнений он MAY написать задание, только если всё это названо в просьбе или однозначно следует из истории. Если просьба расходится с историей по времени, месту или героям, соавтор MUST спросить об этом до задания. Если тема слишком широка для одного исследования, он MUST предложить разбить её на 2–3 задания и писать их только по согласию автора. Соавтор MUST NOT утверждать, что исследует тему сам, и MUST NOT подменять задание своими поисками в интернете: поиск — для отдельных фактов в ответе, а не для исследования темы. Отвечая на вопрос о фактах, он MAY предложить задание словами, не составляя его. Перед блоком он MUST писать одну короткую фразу (например, «Готово — задание для Deep Research:»), после блока — ничего; текст задания и пересказ кнопок блока вне блока MUST NOT появляться.

#### Scenario: Просьба изучить
- GIVEN режим соавтора — `auto`, история «Тихая вода»
- WHEN автор пишет «хочу изучить, как жили паромщики на Волге в 90-е»
- THEN соавтор MUST задать не больше двух уточнений или написать блок задания
- AND он MUST NOT писать, что сам проводит исследование
- AND он MUST NOT отвечать на просьбу пересказом найденного в интернете вместо задания

#### Scenario: Расхождение с историей
- GIVEN история «Последний паром» идёт в наши дни
- WHEN автор пишет «хочу изучить, как жили паромщики на Волге в 90-е»
- THEN соавтор MUST спросить, нужно ли прошлое героя или сегодняшний день, и MUST NOT писать блок задания в этом ответе

#### Scenario: Всё названо
- GIVEN режим соавтора — `auto`
- WHEN автор пишет «составь задание на исследование: как сегодня закрывают сельскую паромную переправу на Нижней Волге после открытия моста, для сцен последнего дня переправы»
- THEN соавтор MUST написать блок задания без уточнений

#### Scenario: Мир книги
- WHEN автор пишет «пишу книгу про Русь XV века, хочу понять обычаи того времени»
- THEN соавтор MUST спросить, какие сословие, место и стороны жизни важнее, и MUST NOT писать блок задания в этом ответе

#### Scenario: Широкая тема
- GIVEN автор ответил «всё: и семья, и праздники, и еда, и вера, и право»
- WHEN соавтор продолжает
- THEN он MUST предложить 2–3 задания по сторонам темы и MUST NOT писать их без согласия автора

#### Scenario: Вопрос о факте
- GIVEN автор спрашивает «Какие удочки были у подростков в 98-м?»
- WHEN соавтор отвечает
- THEN он MUST NOT писать блок задания без просьбы автора

#### Scenario: Одна фраза
- GIVEN автор ответил на уточнения
- WHEN соавтор пишет задание
- THEN перед блоком MUST быть не больше одной фразы, а после блока — ничего

### Requirement: Справка о сервисе у соавтора
В промпте соавтора MUST быть короткая справка о сервисе «Соавтор», составленная по мастер-спекам фронтенда и ядра. На вопрос о сервисе соавтор MUST отвечать по справке. Если ответа в справке нет, он MUST сказать, что не знает, и MUST NOT описывать кнопок, экранов, функций и тарифов, которых в справке нет. Справка MUST меняться вместе с изменением интерфейса, о котором в ней говорится. Справка MUST говорить, что соавтор может искать факты в интернете и что поиск тратит лимит соавтора.

#### Scenario: Экспорт
- GIVEN справка говорит, что в меню «⋯» редактора «Экспорт» сохраняет Fountain и Final Draft, а «Печать…» даёт PDF с титульной страницей
- WHEN автор спрашивает «Как выгрузить сценарий в PDF?»
- THEN соавтор MUST назвать «Печать…» и MUST NOT придумывать других кнопок или форматов

#### Scenario: Нет в справке
- GIVEN в справке нет сведений о мобильном приложении
- WHEN автор спрашивает «Есть ли у вас приложение для телефона?»
- THEN соавтор MUST сказать, что не знает, и MUST NOT утверждать, что приложение есть или его нет

#### Scenario: Вопрос об интернете
- WHEN автор спрашивает «Ты умеешь искать в интернете?»
- THEN соавтор MUST ответить по справке: ищет факты в интернете со ссылками на источники, поиск тратит лимит
