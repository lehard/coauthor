# Proposal: импорт файла из чата соавтором

Источник: `business-intents/coauthor-import-from-chat.md` (решение владельца 2026-11-21). Опора — слитое изменение
`coauthor-typed-suggestions` (`openspec/changes/archive/2026-11-21-coauthor-typed-suggestions/`).

## Why

Сценарий импортируют только кнопкой «Импорт» в меню редактора или при создании истории из файла. Автор хочет
прикрепить файл к сообщению и сказать соавтору «импортируй это» или «вставь вторую сцену из файла после сцены в
баре». Сейчас соавтор читает файл беседы только плоским текстом (`read_chat_file`): импортировать он не может, а
для вставки ему пришлось бы угадывать типы абзацев, которые разбор импорта уже знает.

## What Changes

- **Новый драфт из файла беседы.** Новый меняющий инструмент соавтора: файл, прикреплённый к этой беседе,
  становится новым драфтом текущей истории. Это копия драфта беседы, как при «Новый драфт», а текст сценария в ней
  заменён разобранным файлом. Разбор тот же, что у кнопки «Импорт» (`parse_manuscript`); недостающие персонажи и
  локации добавляются. Драфт беседы не меняется. Имя драфта соавтор передаёт явно: имя файла без расширения, если
  автор не назвал другое.
- **Новая история из файла беседы.** Второй меняющий инструмент — только по прямой просьбе автора («сделай из этого
  новую историю»). Работает по правилам «Новой истории из файла»: файл сохраняется в новой истории с назначением
  `import`, её владелец — пользователь запуска.
- Оба инструмента ставят запуск на паузу, как все меняющие: в режиме `ask` подтверждает автор, в режиме `auto` чат.
  Ничего не затирается. Файл другой беседы и формат, который импорт не разбирает (PDF, MD), дают явный отказ с
  перечнем форматов импорта. Подмены вроде «импорта как простого текста» нет.
- **Сцены файла беседы с типами.** Новый читающий инструмент: для файла формата импорта он отдаёт список сцен
  файла, а по номеру сцены — её абзацы `{type, text}` ровно так, как их разбирает импорт. Соавтор переносит их в
  `suggest_edit` без переразметки. Для PDF и MD — отказ со ссылкой на `read_chat_file`.
- **Перенос строки в абзаце предложения.** Импорт сохраняет перенос строки внутри абзаца (реплика «Фыва\nывафы» из
  Fountain или FDX). Владелец 2026-11-21: вставка из файла должна быть «чётко так, как было в другом формате».
  Поэтому проверка абзацев предложения больше не отклоняет `\n` внутри абзаца (`\r` по-прежнему отклоняется).
  Карточка предложения показывает такой абзац с переносом, «Принять» вставляет его как есть.
- **Чат.** Строка о сделанном ведёт в созданный драфт или историю, а список драфтов и полка историй обновляются без
  перезагрузки. Карточка подтверждения называет имя нового драфта или истории (файл, как у «В заметки», по `id` не называется).
- **Промпт соавтора.** Объясняет, когда импортировать, а когда вставлять предложением. Справка «О сервисе
  «Соавтор»» описывает импорт из чата.
- **Замер действий.** Просьбы могут прикладывать файл из набора замера. Добавляются «импортируй файл» с проверкой
  нового драфта и «вставь сцену из файла после …» с проверкой абзацев предложения против разбора файла.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `api/agents`:
  - «Инструменты соавтора» — новый читающий инструмент и два меняющих; из списка запретов уходят «драфтов, историй
    и импорта» в части создания из файла беседы.
  - Новые требования: «Новый драфт из файла беседы», «Новая история из файла беседы», «Сцены файла беседы»,
    «Вставка из файла беседы».
- `api/story-import`: новые требования «Разбор файла беседы», «Новый драфт из файла беседы в ядре», «Новая история
  из файла беседы в ядре», «Сцены файла беседы в ядре», «Отказ разбора файла беседы». Маршрут
  `POST /api/v1/drafts/{id}/import` по-прежнему отвечает `422` на файл чата.
- `api/review`: «Проверка абзацев предложения» — перенос строки внутри абзаца разрешён.
- `web/workspace`:
  - «Сделанное соавтором в чате» — ссылка на новый драфт или новую историю.
  - «Подтверждение действия соавтора» — карточки двух новых действий.
  - «Экраны после действия соавтора» — список драфтов и полка историй.
  - «Карточка предложения абзацами» и «Предложение абзацами в тексте» — абзац с переносом строки.
- `coauthor-actions-eval`:
  - «Набор просьб замера действий» — просьбы с файлом.
  - «Проверки замера действий» — проверка нового драфта и абзацев из файла.

`api/files` не меняется: новое назначение файла не нужно. Импорт читает файл беседы на месте, а новая история
сохраняет свою копию с назначением `import`, как сейчас.

## Scope

- Ядро: `agno/core/imports.py` — новый драфт из файла беседы, история из файла беседы, сцены файла с типами;
  `agno/core/review.py` — перенос строки в абзаце предложения.
- Соавтор: `agno/agents/coauthor_tools.py` — три инструмента, два из них в `CHANGING_TOOLS`; промпт и справка в
  `agno/skills/coauthor/SKILL.md`.
- Чат: `web/src/screens/project/chat/actions.ts` (`CHANGING_TOOLS`, карточки, цели `draft` и `project`) и
  `ActionLines.tsx` (ссылка). Карточка предложения: `web/src/screens/project/docs/SuggestionViews.tsx`.
- Замер действий: `agno/evals/coauthor/actions.toml`, `actions.py`, `actions_run.py` и файлы набора.
- Тесты: pytest ядра и инструментов на реальном PostgreSQL, `check:chat` фронтенда.

## Non-goals

- Замена текста драфта беседы импортом из чата: она остаётся только кнопкой «Импорт».
- Импорт PDF и MD как сценария, новые форматы и изменения разбора файлов.
- Изменения мест предложения и остальных проверок абзацев.
- Переход беседы в новый драфт: беседа остаётся в своём драфте, автор переходит по ссылке.
- Новое назначение файла и изменения лимитов места.
- Импорт из файла прошлого сообщения без его `id`: соавтор знает `id` только из сообщения, к которому файл
  прикреплён (как у «В заметки»).

## Impact

- Схема базы не меняется.
- Список предложений может вернуть абзац с `\n`: единственный клиент `web/` меняется в том же релизе.
- Тесты: `agno/tests/test_imports*.py`, `test_review*.py`, `test_coauthor_tools.py`, `test_coauthor_actions.py`.
