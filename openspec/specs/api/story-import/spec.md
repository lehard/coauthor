# api/story-import Specification

## Purpose
Импорт рукописи в историю на бэкенде: файлы Fountain, FDX, DOCX и TXT переводятся в текст сценария, персонажей и локации — новой историей или заменой текста существующей.

## Requirements

### Requirement: Новая история из файла
`POST /api/v1/projects` в `multipart/form-data` с непустым `title` и файлом `file` MUST проверить файл как загрузку для импорта (размер, тип, ClamAV), создать историю с текстом сценария из файла, персонажами и локациями из текста и сохранить файл в ней с `purpose` `import`. Если проверка или разбор не удались, история и файл MUST NOT создаваться.

#### Scenario: История из Fountain
- WHEN автор создаёт историю «Паром» из Fountain-файла с тремя сценами
- THEN текст сценария MUST содержать три заголовка сцены с разными `uid`
- AND файл MUST быть в истории с `purpose` `import`

#### Scenario: Битый файл при создании
- WHEN автор создаёт историю из FDX с нарушенным XML
- THEN ответ MUST быть `422` с причиной, и у автора MUST NOT появиться новой истории

### Requirement: Замена текста импортом
`POST /api/v1/drafts/{id}/import` с `file_id` и `If-Match` ревизии текста сценария драфта MUST сохранять снимок текста с причиной `import`, заменять текст сценария этого драфта текстом из файла и добавлять в него недостающих персонажей и локации. Комментарии и предложения старого текста MUST оставаться в ядре, их метки в новом тексте MUST NOT появляться. Другие драфты MUST NOT меняться. Несовпадение ревизии — `409`, ошибка разбора — `422`, запертый драфт — `409`; в этих случаях драфт MUST NOT меняться.

#### Scenario: Битый файл
- WHEN автор импортирует FDX с нарушенным XML
- THEN ответ MUST быть `422` с причиной, текст и документы драфта MUST NOT меняться

#### Scenario: Файл чата
- WHEN `file_id` указывает на файл с `purpose` `chat`
- THEN ответ MUST быть `422`

#### Scenario: Снимок перед импортом
- WHEN автор импортирует файл в драфт 2
- THEN в истории текста драфта 2 MUST быть снимок с причиной `import` и прежним текстом, а текст драфта 1 MUST остаться прежним

### Requirement: Абзацы сценария из файла
Импорт MUST переводить абзацы в типы сценария редактора: Fountain — по правилам Fountain и пометкам `[[@тег текст]]` нашего экспорта; FDX — по типам абзацев Final Draft; STARC — по типам абзацев текста сценария STARC; DOCX и TXT — построчно по правилам Fountain. Каждой сцене MUST выдаваться новый `uid`; параметры сцены STARC (название, день истории, цвет, теги) MUST переноситься, если они есть.

Переносы строк внутри абзаца MUST сохраняться символом перевода строки:
- в Fountain (и в TXT по его правилам) строки реплики подряд под одним персонажем без ремарки между ними MUST давать одну реплику, строки действия подряд без пустой строки — одно действие; строка ровно из двух пробелов внутри такого блока MUST давать пустую строку внутри абзаца;
- пометка `[[…]]` на нескольких строках MUST читаться целиком, строки внутри неё MUST соединяться переводом строки, строка из двух пробелов MUST давать пустую строку;
- в FDX перевод строки внутри текста абзаца MUST сохраняться.

#### Scenario: Русские заголовки в TXT
- WHEN импортируется TXT со строками «ИНТ. КУХНЯ — ДЕНЬ» и «ВЕРА» над репликой
- THEN текст MUST содержать заголовок сцены, персонажа и реплику

#### Scenario: Круг через наш Fountain
- WHEN импортируется Fountain, выгруженный экспортом редактора, с абзацами «Участники сцены» и «Бит»
- THEN эти абзацы MUST вернуться своих типов

#### Scenario: Параметры сцены из STARC
- WHEN импортируется `.starc`, где у сцены есть название, день истории, цвет и теги
- THEN у заголовка этой сцены MUST быть те же название, день, цвет и теги

#### Scenario: Реплика в несколько строк
- WHEN импортируется Fountain с персонажем «ДАРЬЯН» и строками «Фыва» и «ывафы» сразу под ним
- THEN текст MUST содержать персонажа и одну реплику «Фыва\nывафы»

#### Scenario: Действие в несколько строк
- WHEN импортируется Fountain со строками действия «Пывапыв» и «дальше» без пустой строки между ними
- THEN текст MUST содержать одно действие «Пывапыв\nдальше»

#### Scenario: Многострочная пометка
- WHEN импортируется Fountain со строками «[[@parenthetical тихо», «почти шёпотом]]» внутри блока персонажа
- THEN текст MUST содержать ремарку «тихо\nпочти шёпотом»

#### Scenario: Перенос строки из FDX
- WHEN импортируется FDX с абзацем `Dialogue`, в тексте которого перевод строки между «Фыва» и «ывафы»
- THEN текст MUST содержать реплику «Фыва\nывафы»

### Requirement: Персонажи и локации из импорта
Импорт MUST добавлять эпизодическими персонажей из абзацев «Персонаж» (без пометок в скобках) и локации из заголовков сцен (между «ИНТ.»/«НАТ.»/«INT.»/«EXT.» и тире), которых в этом драфте нет без учёта регистра. Из STARC MUST переноситься персонажи и локации проекта с их именами и ролью.

#### Scenario: Без дублей
- WHEN в драфте есть персонаж «Вера», а в импортируемом тексте реплики «ВЕРА» и «ОЛЕГ»
- THEN MUST добавиться только «Олег»

#### Scenario: Персонажи проекта STARC
- WHEN импортируется `.starc` с главным персонажем «Вера», которая в тексте не говорит
- THEN в драфте MUST появиться «Вера» с ролью «главный»

### Requirement: Отказ импорта STARC
Файл `.starc` MUST читаться только на чтение как база SQLite STARC с документом структуры и текстом сценария. Файл другой структуры, без сценария, текст которого есть в файле, с несколькими сценариями, текст которых есть в файле, с неизвестным типом абзаца, неизвестным элементом или неизвестной ролью MUST давать `422` с причиной. Частичного импорта MUST NOT быть, кроме одного случая: запись структуры проекта, у которой в файле нет своего документа (требование «Пропущенное при импорте STARC»).

#### Scenario: Проект романа
- WHEN импортируется `.starc` с романом и без сценария
- THEN ответ MUST быть `422` с причиной «в файле нет сценария»

#### Scenario: Два сценария с текстом
- GIVEN в структуре `.starc` два сценария, и текст каждого есть в файле
- WHEN файл импортируется
- THEN ответ MUST быть `422` с причиной «в файле несколько сценариев», и история MUST NOT создаваться

#### Scenario: Ни у одного сценария нет текста в файле
- GIVEN в структуре `.starc` два сценария, и в файле нет текста ни одного из них
- WHEN файл импортируется
- THEN ответ MUST быть `422` с причиной «в файле нет сценария»

### Requirement: Что импорт STARC не переносит
Известные данные STARC, для которых в редакторе нет места (номер, описание, штамп, время и ресурсы сцены, параметры бита и акта, закладки, зачёркивание, выравнивание, комментарии и правки рецензирования), импорт MUST NOT отклонять и MUST NOT переносить.

#### Scenario: Сцена со штампом
- WHEN импортируется `.starc`, где у сцены есть штамп и закладка
- THEN импорт MUST пройти, а текст сцены MUST перенестись без них

### Requirement: Пропущенное при импорте STARC
Запись структуры проекта STARC вне корзины, у которой в файле нет своего документа — сценарий без документа текста, персонаж или локация без профиля, — MUST считаться отсутствующей в файле: импорт MUST NOT переносить её и MUST NOT отказывать из-за неё. Ответы `POST /api/v1/projects` (история из файла) и `POST /api/v1/drafts/{id}/import` MUST содержать поле `skipped`: список пропущенных записей с видом (`screenplay`, `character`, `location`) и именем из структуры, в порядке структуры. Для файлов других форматов и для файла STARC без таких записей `skipped` MUST быть пустым списком. Запись, документ которой есть, но не разбирается, MUST давать `422`, как прежде, и в `skipped` MUST NOT попадать.

#### Scenario: Облачный проект, выгруженный не полностью
- GIVEN в структуре `.starc` сценарии «Выбор 1» и «Выбор 2», текст есть только у «Выбор 1», а у локации «Колиба» нет профиля
- WHEN автор создаёт историю из этого файла
- THEN история MUST создаться с текстом «Выбор 1» и персонажами и локациями, у которых есть профиль
- AND `skipped` MUST содержать сценарий «Выбор 2» и локацию «Колиба»

#### Scenario: То же при замене текста
- GIVEN тот же файл загружен для импорта в драфт
- WHEN автор импортирует его в драфт
- THEN текст драфта MUST стать текстом «Выбор 1», а `skipped` MUST содержать сценарий «Выбор 2» и локацию «Колиба»

#### Scenario: Полный файл
- WHEN импортируется `.starc`, у всех записей которого есть документы, или файл FDX
- THEN `skipped` MUST быть пустым списком

#### Scenario: Корзина не в списке
- GIVEN в корзине проекта `.starc` есть сценарий без текста в файле
- WHEN файл импортируется
- THEN этот сценарий MUST NOT быть в `skipped`

### Requirement: Разбор файла беседы
Файл с `purpose` `chat` формата импорта (Fountain, FDX, STARC, DOCX, TXT) MUST разбираться теми же правилами, что файл импорта: «Абзацы сценария из файла», «Персонажи и локации из импорта», «Отказ импорта STARC», «Пропущенное при импорте STARC». Ядро делает это только по вызову соавтора (`api/agents`). `POST /api/v1/drafts/{id}/import` MUST по-прежнему отвечать `422` на файл с `purpose` `chat`.

#### Scenario: Маршрут импорта и файл чата
- WHEN `POST /api/v1/drafts/{id}/import` получает `file_id` файла с `purpose` `chat`
- THEN ответ MUST быть `422`, и драфт MUST NOT меняться

### Requirement: Новый драфт из файла беседы в ядре
Ядро MUST создавать из файла беседы новый драфт истории файла: копию заданного драфта этой истории по правилам создания драфта, у которой текст сценария заменён текстом из файла, а недостающие персонажи и локации добавлены. Заданный и другие драфты MUST NOT меняться. Запертая основа MUST NOT мешать: новый драфт создаётся незапертым.

#### Scenario: Новый драфт из Fountain беседы
- GIVEN в истории «Паром» драфт 1 с персонажем «Вера», и к беседе приложен Fountain-файл с тремя сценами и репликами «ВЕРА» и «ОЛЕГ»
- WHEN ядро создаёт из него драфт «Паром — правка» на основе драфта 1
- THEN в истории MUST появиться драфт «Паром — правка», текст сценария которого совпадает по абзацам и типам с текстом, который даёт импорт этого файла кнопкой, а у трёх заголовков сцен разные `uid`
- AND в новом драфте MUST быть «Вера» и добавленный «Олег», а текст и документы драфта 1 MUST остаться прежними

#### Scenario: Основа заперта
- GIVEN драфт 1 заперт
- WHEN ядро создаёт новый драфт из файла беседы на основе драфта 1
- THEN новый драфт MUST появиться незапертым, а драфт 1 MUST остаться запертым и прежним

#### Scenario: STARC с пропуском
- GIVEN `.starc` беседы, где у локации «Колиба» нет профиля
- WHEN ядро создаёт из него новый драфт
- THEN драфт MUST появиться без «Колибы», а результат MUST называть пропущенную локацию «Колиба»

### Requirement: Новая история из файла беседы в ядре
Ядро MUST создавать из файла беседы историю пользователя по правилам «Новая история из файла»: текст сценария из файла, персонажи и локации, копия файла в новой истории с `purpose` `import`. Файл беседы MUST оставаться в прежней истории с `purpose` `chat`.

#### Scenario: Новая история из файла беседы
- WHEN ядро создаёт историю «Паром 2» из Fountain-файла беседы
- THEN у пользователя MUST появиться история «Паром 2» с текстом сценария из файла и копией файла с `purpose` `import`
- AND файл беседы MUST остаться в прежней истории с `purpose` `chat`

### Requirement: Сцены файла беседы в ядре
Ядро MUST отдавать сцены файла беседы: список сцен (номер с 1, текст заголовка, число абзацев) и абзацы одной сцены `{type, text}` в том виде, в каком они попали бы в текст сценария при импорте, с переносами строк внутри абзацев. Номер вне списка MUST давать отказ, называющий число сцен.

#### Scenario: Сцены файла с переносом строки
- GIVEN Fountain-файл беседы, во второй сцене которого персонаж «ДАРЬЯН» и строки «Фыва» и «ывафы» сразу под ним
- WHEN ядро отдаёт абзацы сцены 2 этого файла
- THEN среди них MUST быть `{type: "character", text: "ДАРЬЯН"}` и `{type: "dialogue", text: "Фыва\nывафы"}`

#### Scenario: Сцены нет
- GIVEN в файле беседы три сцены
- WHEN ядро отдаёт абзацы сцены 4
- THEN MUST быть отказ, называющий число сцен файла

### Requirement: Отказ разбора файла беседы
Файл другой истории, формат не из списка импорта (PDF, MD), битый файл или отказ разбора MUST давать отказ с причиной; у формата не из списка причина MUST перечислять форматы импорта. При отказе MUST NOT появляться ни драфта, ни истории, ни документов, ни файла. Разбирать такой файл как простой текст MUST NOT.

#### Scenario: PDF не импортируется
- WHEN ядро создаёт новый драфт или новую историю из `Эпоха.pdf` беседы
- THEN MUST быть отказ, перечисляющий Fountain, Final Draft, STARC, DOCX и TXT, и MUST NOT появиться ни драфта, ни истории

#### Scenario: Битый FDX беседы
- WHEN ядро создаёт новый драфт из FDX беседы с нарушенным XML
- THEN MUST быть отказ с причиной, и драфт MUST NOT появиться
