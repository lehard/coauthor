# Бизнес-интент: соавтор ищет в интернете через Yandex Search API

Статус: решения согласованы с владельцем 2026-11-16 и 2026-11-17; change `coauthor-web-search` реализован, проверен локально и архивирован 2026-11-17 (`openspec/changes/archive/2026-11-17-coauthor-web-search/`, проверки — `tmp/VERIFY.md`); не выкачен. Добавлено при реализации (владелец, 2026-11-17): не чаще одного запроса к Яндексу в секунду на процесс. Владелец: lehard. Обновлено: 2026-11-17.
Рамки: спеки `api/agents` («Соавтор»), `billing/subscriptions` («Цены моделей как данные»), `integrations`; `openspec/context/07-anti-patterns.md` (п. 26: fallback-и).

## Why

Соавтор работает на DeepSeek через API, а у API своего поиска нет. Поэтому соавтор знает только то, что попало в обучение модели, плюс историю и библиотеку источников (`search_story`, `search_sources`). Если автору нужен факт извне (быт эпохи, профессия, место, дата, реалия), соавтор отвечает по памяти модели и может выдумать.

Варианты обсуждали с владельцем 2026-11-16 и 2026-11-17:

- Западные API для агентов (Tavily, Exa, Brave, Perplexity, около $5–8 за 1000 запросов). Русский интернет они индексируют слабее, платить нужно в долларах, а запросы с кусками сюжета уходили бы в США. Отклонены.
- Яндекс, генеративный ответ (5 080 ₽ за 1000) и смарт-сниппеты (1 500 ₽ за 1000). Владелец счёл их дорогими.
- Отложенные запросы Яндекса (25–30,5 ₽ за 1000). Они работают только с 00:00 до 06:00 по Москве, и ответ приходит не сразу, так что для чата не годятся.
- Бесплатные DuckDuckGo и свой SearXNG. Доступ неофициальный, они часто отказывают, а запасной поисковик на такой случай был бы fallback. Отклонены.

**Решение владельца (2026-11-17):** обычный синхронный поиск Yandex Search API: 488 ₽ за 1000 запросов днём и 366 ₽ ночью (00:00–08:00 МСК), цены с НДС. Индекс рунета у Яндекса лучший, расчёты в рублях.

## What Changes

1. **Новый инструмент соавтора `web_search(query)`.** Это инструмент чтения, подтверждения автора не требует. Он делает синхронный запрос к Yandex Search API v2 (`SEARCH_TYPE_RU`, регион вся Россия `lr=225`, выдача в XML; владелец, 2026-11-17), берёт первые 5 результатов, для каждого до 5 отрывков (`maxPassages=5`) и возвращает модели короткий текст: номер, заголовок, адрес, отрывки. Разбирать XML и следить за форматом ответа будет наш код.
2. **Не больше 2 поисков на один ответ соавтора.** Третий вызов за запуск возвращает отказ строкой «Отказ: …», без запроса к Яндексу.
3. **Каждый поиск оплачивается из лимита автора.** Цена поиска хранится в данных биллинга рядом с ценами моделей: одна дневная цена 0,488 ₽ за запрос в любое время суток, ночью расход завышается не больше чем на четверть (владелец, 2026-11-17). Биллинг записывает число поисков в запуске и добавляет их стоимость к расходу запуска. Если цены поиска нет в данных, API не запускается, как сейчас без цены модели.
4. **Правила в промпте соавтора** (`agno/skills/coauthor/SKILL.md`):
   - искать только факты и реалии внешнего мира, когда без них ответ получится выдуманным;
   - о самой истории спрашивать `search_story`, о теории драматургии `search_sources`;
   - в запрос не вставлять текст сценария и личные данные, писать короткий поисковый запрос своими словами;
   - в ответе давать автору ссылки на страницы, по которым сделан вывод;
   - если поиск отказал, говорить автору об этом прямо и не выдавать ответ по памяти за найденный.
5. **Сбой поиска виден явно.** Если Яндекс отказал (ошибка, квота, неверный ключ, пустой или нераспознанный ответ), инструмент возвращает отказ с причиной и пишет ошибку в лог API. Повтора и запасного поисковика нет.
6. **Настройки.** API-ключ сервисного аккаунта (роль `search-api.webSearch.user`) и идентификатор каталога Yandex Cloud задаются переменными окружения. Без них API не стартует (п. 26, без fallback). Их добавляем в `example.env` и в `/etc/authorled/authorled.env` на сервере.

## Scope

- `agno/agents/`: клиент Yandex Search API и инструмент `web_search` (в `coauthor_tools.py` или в отдельном модуле, который он импортирует), инструмент добавляется в `READING_TOOLS`.
- `agno/billing/`: цена поиска в данных (`model_prices.toml` или отдельный раздел), поле с числом поисков в `RunUsage`, расход запуска с учётом поисков, миграция `billing`, если нужна новая колонка.
- `agno/agents/coauthor_usage.py`: считать вызовы `web_search` в `RunOutput` и передавать их в биллинг.
- `agno/skills/coauthor/SKILL.md`: правила поиска, справка «О сервисе «Соавтор»».
- `example.env`, README (настройки), спеки `api/agents`, `billing/subscriptions`, `integrations`.
- Тесты: разбор XML-ответа на сохранённом образце, отказ после второго поиска, расход запуска с поисками в биллинге.
- Проверка на локальном стенде на настоящем ключе: 3–5 запросов автора, которым нужен факт извне. Результат записать в `tmp/VERIFY.md`.

## Non-goals

- Чтение страницы целиком по ссылке (загрузчик вроде `trafilatura`). Это отдельный интент, если отрывков окажется мало.
- Генеративный ответ, смарт-сниппеты, поиск по картинкам.
- Кэш одинаковых запросов.
- Запасной поисковик и повтор при сбое Яндекса (п. 26).
- Поиск для других агентов. Parallel в реестре Studio (`agno/app/registry.py`) не меняется.
- Показ найденных ссылок в интерфейсе отдельным блоком. Ссылки приходят в тексте ответа соавтора.

## Constraints (из контекст-пака)

- Без fallback: нет ключа — нет старта; отказ Яндекса — явный отказ инструмента (07-anti-patterns, п. 26).
- Список инструментов соавтора статический: AgentOS 3.1.10 не принимает инструменты, созданные на каждый запуск.
- Биллинг ничего не импортирует из ядра, `app/`, `agents/` и Agno (`check_billing_boundary.sh`). Число поисков передаётся в биллинг простым значением.
- Ключ не выводится в чат, логи и файлы репозитория.

## Acceptance criteria

- На вопрос, которому нужен факт извне («какие сигареты курили в Москве в 1972 году»), соавтор вызывает `web_search`, отвечает по найденному и даёт ссылки.
- На вопрос о самой истории соавтор в интернете не ищет.
- За один ответ проходит не больше 2 запросов к Яндексу, третий вызов возвращает отказ.
- Стоимость поисков входит в расход запуска в отчёте `admin report` и уменьшает остаток лимита автора.
- При неверном ключе соавтор говорит автору, что поиск недоступен, а в логе API есть ошибка Яндекса. Ответ по памяти за найденный не выдаётся.
- Без переменных Яндекса API не стартует, и сообщение называет недостающую переменную.

## Risks

- **Отрывков может не хватить.** Обычная выдача даёт короткие пассажи, а не текст страницы. Если ответы получатся поверхностными, понадобится чтение страницы (non-goal, следующий интент) или смарт-сниппеты.
- **Квота по умолчанию 1 запрос в секунду.** Если несколько авторов ищут одновременно, часть запросов получит отказ. Для беты этого хватает, квоту поднимают через поддержку Yandex Cloud.
- **Данные запросов.** Запросы уходят в Яндекс. Сюжет туда попадать не должен, это держится только на правиле в промпте.
- **Формат XML не описан полностью**, все поля в документации необязательные. Разбор пишется по реальному ответу, а при неизвестной структуре инструмент отказывает явно.
